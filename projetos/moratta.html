Moratta

Um sistema de gestão de condomínios: cadastros, finanças, contratos e relatórios, com cada pessoa vendo só o que o seu papel permite.

01O problema

Administrar um condomínio envolve muita gente e muito dado: moradores, imóveis, funcionários, cobranças, pagamentos, despesas e contratos. Cada pessoa precisa ver uma parte diferente disso. O administrador vê tudo, um funcionário vê só o que é da sua função, e um futuro morador só preenche o próprio pré-cadastro.

O Moratta é a aplicação web que junta tudo isso. Este repositório é o frontend, que consome as APIs REST do backend.

02Arquitetura

A aplicação usa o App Router do Next.js, organizada por funcionalidade e não por tipo de arquivo:

src/app/condominios/[condId]/rotas por condomínio, separadas em grupos (admin) e (public)
↓
(admin)layout protegido por sessão, sidebar filtrada pelo papel do usuário
(public)páginas abertas, como o pré-cadastro de moradores
↓
src/features/<módulo>/components · services · schemas · hooks, para cada módulo (usuarios, condominos, imoveis, cobrancas…)
↓
TanStack Querycache e estado das requisições
APIs REST do backendcom mocks para desenvolver sem depender dele

03O que eu construí

Tela de administração de usuários

A página de usuários do condomínio, com filtros, diálogo para adicionar usuários e mutations e queries separadas em hooks. Reorganizei os componentes de usuário para dentro de features/usuarios, seguindo o padrão do projeto.

Migração para a tabela genérica

O projeto tem um data-table genérico sobre o TanStack Table, reutilizado pelos módulos com colunas próprias. Migrei a tabela de usuários para esse componente, eliminando a implementação duplicada.

Tela de condôminos

Listagem de moradores com filtros e um diálogo de visualização com os dados completos de cada condômino, além das rotas de API correspondentes.

Autenticação e controle de acesso

  • Proteção do layout de administração com a sessão do NextAuth.
  • Status do usuário na sessão, para o frontend saber o que mostrar.
  • Correções nos filtros de usuários e de moradores e nos tipos compartilhados.

Pré-cadastro público

Um formulário aberto para novos moradores, feito com React Hook Form e validação por schema Zod. A mesma regra de validação vale para a interface e para os tipos TypeScript.

04O que o projeto me ensinou

Foi um projeto de equipe com branches por funcionalidade e pull requests para a develop. Boa parte do trabalho foi integrar a minha branch com as dos outros (auth, tela de admin, condôminos) sem quebrar o que já funcionava.
